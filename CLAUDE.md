# OrGanuz AI Site Test Automation

Playwright + TypeScript test suite for Organuz, plus a local FastAPI/Prometheus/Grafana + Pushgateway stack that turns Playwright results into a QA dashboard. QA metrics are **pushed** to the Prometheus Pushgateway by the test runner (`scripts/push-qa-metrics.mjs`), not read from a file by the API.

- **`agent`** → `tests/agent/**` → QA-agent unit specs (stubs, no network/browser): the orchestrator run-loop spec and the `TestPlanAgent` spec (URL → Playwright-MCP exploration → generated test plan), default-filtered to `@other-smoke`.
- **`security`** → `tests/security/**` → **authorized, non-destructive penetration testing** of the Organuz Supabase backend with the public anon key only (browserless `APIRequestContext`), 30 checks across auth, RLS/authz (anon-write denied, mass-delete guard, privileged endpoints blocked, no sensitive fields), injection (SQLi treated as data, JSON-not-HTML errors, no reflected XSS, no 5xx), transport (HTTPS + cert), CORS (no wildcard-origin+credentials), key hygiene (anon role, unexpired, no `alg:none`), edge-function auth, and **account takeover** (SEC-21..30: forged-credential login, forged/replayed refresh token, forged & `alg:none`/tampered JWTs rejected, wrong-OTP no-session, no account enumeration, bad-login-burst resistance, admin user-provisioning blocked, auth error hygiene). A failure here is a real security finding. In the CI matrix.
- **`fraud`** → `tests/fraud/**` → **authorized, non-destructive fraud / account-takeover (ATO) testing of the Organuz PRODUCT app** (the calculator origin + its auth/RPC backend) for the env selected by `QA_TARGET_ENV` (dev `dev1.app.organize.organuz.com` default, prod `energy.organuz.com` on demand), 14 checks (8 ATO + 6 anti-fraud). Browserless `APIRequestContext`; sibling of `security` (which targets the organuz.ai Supabase backend). **Two tiers of certainty:** *app-origin* checks (transport/HTTPS+redirect, HSTS, clickjacking headers, CORS-with-credentials, secret/cookie hygiene, reflected-XSS) run correctly on **both** dev and prod against the env-resolved origin; *auth-backend* checks (forged/empty-token rejection, injection→JSON-not-HTML, error non-leakage, OTP brute-force uniformity, backend CORS) **self-skip via a reachability canary** (`authBackendBlockReason`) when the gateway is unreachable or serves an HTML block/challenge page — the same env-gated skip pattern as `monitoring`. A genuine finding (forged creds honoured, secrets leaked, wildcard-CORS+creds) **fails** — a real fraud finding. Non-destructive by construction: every identity is fabricated (`FAKE`) so login/verify can only fail, and the suite **never triggers an OTP send** (verify-only). Two probes are env/contract-gated (sanctioned skips): **ATO-08** (dev magic OTP `7777` must not authenticate on prod) skips on dev (where 7777 is an intentional convenience) and until `FRAUD_OTP_VERIFY_CALL` names the live verify method; **FRAUD-05** (OTP brute-force) skips until the same var is set. Two hardening-header checks (**ATO-02** HSTS, **ATO-03** clickjacking) are **prod-strict / dev-informational**: they hard-fail on prod but only annotate a `known-gap` on the gated dev app (which currently sends neither) — an explicit, documented env split so the default dev pipeline stays green. In the CI matrix (dev). Endpoints resolve per-env from config; overridable via `FRAUD_AUTH_BACKEND` / `FRAUD_APP_TOKEN` / `FRAUD_OTP_VERIFY_CALL`.
- **`local-web`** → `tests/local-web/**` → **local-only** marketing-site e2e (real Chromium against prod `www.organuz.ai`), ~50 specs. Every spec **self-skips when `process.env.CI` is set** (see `tests/local-web/support.ts`) and the project is **not** in the `parallel-tests.yml` CI matrix — an intentional, sanctioned local/CI divergence (see the `test-suite-parity` skill).
- **`monitoring`** (opt-in) → `tests/monitoring/**` → dedicated availability/contract monitoring for the critical external map dependencies **Govmap** (`www.govmap.gov.il` — map API + address geocoding) and **Ofek** (`basemaps.govmap.gov.il` — Survey-of-Israel orthophoto tiles), 25 checks each. Uses `APIRequestContext` (no browser). **Not in the default local suite**: registered only when `MONITORING_ENABLED=true` (`npm run test:monitoring`), and it is *meant to fail* when a dependency breaks — that is the alert. On GitHub Actions it runs two ways: (1) a 30-min cron in `.github/workflows/monitoring.yml` (a failure opens an auto-managed GitHub issue + pings both Slack webhooks; the next green run closes it); (2) a **non-blocking `monitoring` job in `parallel-tests.yml`** that runs on every push/PR — `continue-on-error: true`, so a Govmap/Ofek outage shows the job red and folds into the Allure report but **never fails the code pipeline / green PR gate**. Endpoints/tokens/tile coords live in `config.json → monitoring`. A per-worker canary in `tests/monitoring/support/availability.ts` (`govmapBlockReason`/`ofekBlockReason`, called from each spec's `beforeEach`) makes the group **skip** (not fail) when the govmap.gov.il edge serves an HTML block/challenge page to the runner (a geo/bot block, e.g. a CI runner outside Israel); a real break (5xx, connection error, or a real-but-wrong non-HTML payload) still fails — so a red monitoring run now means a genuine dependency break, not a blocked runner.

## Environments & secrets
- `QA_TARGET_ENV` selects the product target; `APP_BASE_URL`/`APP_ADMIN_URL` override explicitly.
- Local overrides + credentials live in **gitignored per-target env files** under `env/`: **`env/.dev.env`** (loaded when `QA_TARGET_ENV=dev`, the default) and **`env/.prod.env`** (`QA_TARGET_ENV=prod`), selected by `QA_TARGET_ENV` in `playwright.config.ts` + `scripts/run-all-tests.sh`. Variable names inside each file are **unprefixed** (`CUSTOMER_PHONE`, not `DEV_CUSTOMER_PHONE`) — the file scopes them. An optional root `.env` is a shared fallback (the env-specific file wins). Committed templates: `env/.dev.env.example` / `env/.prod.env.example` (+ `env/README.md`). Restricted — from the "Organuz Environments" doc; never commit real env files or move credentials into committed files.
- Dev/Test product apps sit behind a shared password gate (`PRODUCT_PLATFORM_PASSWORD`); the token-sanity spec needs it to open the dev calculator. On CI it's the `PRODUCT_PLATFORM_PASSWORD` GitHub repo secret (see the `test-suite-parity` skill).
- The live per-role specs (`product-setup` → `product-authenticated`) need per-role phone/OTP creds: `<ROLE>_PHONE` / `<ROLE>_OTP_CODE` for `CUSTOMER`, `CONSULTANT`, `COMPANY` (in `env/.<target>.env`; wired as GitHub secrets in the workflow). Resolved env-aware in `tests/product/support/roleCredentials.ts` (accepts a legacy `<ENV>_<ROLE>_PHONE` fallback). Absent → those roles skip.
- Slack alerting (optional, any/all): `SLACK_WEBHOOK_URL`, `SLACK_WEBHOOK_BOT_URL`, and `SLACK_ORGANUZ_TESTING_URL` (the **#organuz-testing** channel). Used by `run-all-tests.sh` and the `parallel-tests.yml` report-summary step to post the run status + Allure / Grafana / Playwright HTML / Scalar report links after a run (all three webhooks), and by `.github/workflows/monitoring.yml` to ping on a Govmap/Ofek outage (the first two webhooks). `REMOTE_HREF` is the GitHub repo home used for report/remote links. Local: gitignored `env/.<target>.env`; CI: GitHub repo secrets of the same names. Smoke-test the wiring with `./scripts/slack-alert-test.sh` (posts a clearly-marked test to every configured webhook; never prints the URLs). Absent → that post is skipped, not failed.

## Conventions
- Specs import `test`/`expect` from `src/fixtures` unless a domain-specific support fixture extends it (for example `tests/ui/support/fixtures` or `tests/product/support/fixtures`). Use the `allureEpic/Feature/Story/Severity/Step` helpers with `@tag`s.
- Run `npx tsc --noEmit` before running tests.
- `organuz-api` (1) and `agent` (2) run only their `@other-smoke`-tagged tests by default (chromium 12 when re-enabled); `product` (37), `security` (30), and `local-web` (50, local-only) have no grep filter and run everything matched.
- `local-web` is local-only: every spec self-skips when `process.env.CI` is set, and the project is not in the CI matrix (a sanctioned local⇄CI divergence). `security` is authorized, non-destructive backend penetration testing — a failure is a real finding, not a flake to skip.
- Never use `waitForLoadState('networkidle')` in product tests — the map iframe keeps the network busy; use `domcontentloaded` or `expect` auto-waiting.
- Environmental outages are typed errors in `tests/product/support/errors.ts` (`OtpUnavailableError`, `AppUnavailableError`) — `instanceof`-safe (they set the prototype/name, since Playwright's transpiler otherwise severs `extends Error`). `ProductAppPage`/`env-gate`/`ProductFlows` **throw** them; the test edge (spec or fixture) decides whether to skip or fail. Keep skip/lifecycle logic out of the page object and the flows.
- The suite stays all-green with no failures. Sanctioned skips (never failures): (1) the `token-sanity` spec (3 tests) skips when the live dev gateway/gate is down and no UI token can be extracted — a token that IS observed but malformed/drifted still fails as a real regression; (2) the live per-role specs (`product-setup` 3 + `product-authenticated` 10) skip when a role has no credential/saved session, so they are dormant on CI until per-role secrets are added; (3) the calculator **wizard e2e** specs (`tests/product/wizard/**` — `calculator-wizard-e2e` + `customer-process-e2e`): the checks that drive the **live address geocode** are **local-only** (they call `skipGeocodeDrivingOnCi()` in `tests/product/support/envGate.ts`, which `test.skip`s on `process.env.CI` because the govmap geocode is geo-blocked/flaky for CI runners — the same divergence as `local-web`), and the authenticated-characterization check is additionally opt-in behind `PRODUCT_WIZARD_E2E=true` (it creates a real dev project + needs customer login) and self-skips on OTP cooldown. The deterministic step-tracker checks still run on CI. Outside those environment-gated cases, no test should `test.skip()` — it should run or be removed (see the `test-suite-parity` skill). (The opt-in `monitoring` group has one further sanctioned skip: it skips when the govmap.gov.il edge serves an HTML block/challenge page to the runner — see the monitoring bullet above.)

## Skills
Project skills live in `.claude/skills/`. Invoke with `/<name>`:
- **`organuz-run-tests`** — run the suites against the right project/environment, the `run-all-tests.sh` orchestrator, and the local server stack (Pushgateway-based metrics, ports, port-8000 conflict, empty-Grafana-panels).
- **`organuz-product-e2e`** — drive/debug the product calculator end-to-end: dev password gate, phone+OTP login UI, the characterization wizard (confirmed dev selectors/URLs), the `ProductFlows` fixture, and MCP driving. Use when working on `tests/product/**` or exploring dev with the Playwright MCP.
- **`organuz-product-roles`** — per-role auth & session reuse (`product-setup` + `storageState` + `resumeSession`), the customer/consultant/company roles and their personal areas, and the role specs under `tests/product/flows`. Use when writing/fixing per-role product tests, the auth setup, or the product fixtures.
- **`organuz-api-tests`** — write/debug contract & API tests against the Organuz Supabase backend (`tests/organuz-api/**`): projects REST resource, anon key, RLS, edge-function preflights.
- **`organuz-monitoring`** — build/debug the Grafana+Prometheus+Pushgateway stack: dashboards from `qa_playwright_*` metrics (pushed via `scripts/push-qa-metrics.mjs`), the process CPU/mem/network metrics from the FastAPI `/metrics`, and the port-8000 gotcha.
- **`test-suite-parity`** — keep the Playwright suite identical locally and on GitHub Actions (same projects/tests, all green). Use when adding/removing a test or project, editing `playwright.config.ts`, or `.github/workflows/parallel-tests.yml`.
- **`organuz-hebrew-tests`** — the language split in the specs. The **report layer is now English** (describe/test titles, Allure epic/feature/story/step labels, comments, and assertion messages were translated out of Hebrew); Hebrew remains only in **DOM assertions/selectors, expected on-page content, and data constants** that must match the live Hebrew site/app. Use when adding/editing specs to keep that split (English↔Hebrew glossary included).
- **`organuz-product-en`** — the English-version product-app sanity tests (`tests/product/en/**`, `tests/product/flows/roles-en.spec.ts`): the header language switch (`עברית` → `English`, persisted in `localStorage`), the `switchToEnglish()`/`currentLanguage()` helpers, and the public + per-role EN specs for the 6-step calculator site. Use when editing the EN specs or the language-switch code.
- **`flaky-test-triage`** — detect a flaky test (fails ≥1 of ≥3 runs but not all), tag it `@KNOWN_FLAKY`, and file an idempotent bug in Azure DevOps (Jira as the alternate). Use when a test intermittently fails or when wiring flaky detection/quarantine.
- **`organuz-fraud-detection`** — the `fraud` project (`tests/fraud/**`): non-destructive fraud / account-takeover testing of the product app across dev & prod (`QA_TARGET_ENV`), the app-origin vs auth-backend two-tier model, the reachability canary, the fabricated-identity/verify-only guarantees, and the `FRAUD_*` overrides. Pairs with `test-suite-parity`. Use when editing `tests/fraud/**` or adding fraud/ATO checks. Shares the `HttpStatus` constants (`src/utils/httpStatus.ts`) with `security`/`organuz-api`.

Per-test-group skills (how to run/extend one group; see the mapping in `Architecture.html`):
- **`ui-sanity-tests`** — the `chromium` marketing-site sanity group (`tests/ui/**`, visibility-only `@other-smoke`).
- **`product-public-sanity`** — the no-login dev-calculator checks (`tests/product/api/**`: token-sanity + public-app-sanity), skip-on-outage.
- **`product-matrix-contract`** — the offline matrix & role data-contract specs (`tests/product/matrix/**`).
- **`product-roles-e2e`** — the live per-role browser group (`product-setup` → `product-authenticated`, `tests/product/flows/**`); pairs with `organuz-product-roles`.
- **`external-api-monitoring`** — the live Govmap + Ofek `monitoring` group (`tests/monitoring/**`): browserless `APIRequestContext` health checks, the three auth tiers (no-token search / domain-bound token / referer-gated tiles), `config.json → monitoring` env overrides, and the CI/cron alerting. Use when editing `tests/monitoring/**` or the endpoints helper.
