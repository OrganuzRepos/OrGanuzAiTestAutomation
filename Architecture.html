The architecture behind OrGanuz AI test automation

A single-file architecture view for the OrGanuz AI site automation stack. Local runs start the runtime services, execute the active Playwright projects, generate Allure 3, and print the main service links. Seven projects are active by default — product (60 discovered calculator cases), organuz-api (Supabase/PostgREST), agent (orchestrator + TestPlanAgent), security (backend penetration checks), fraud (product fraud/ATO), local-web (local-only marketing e2e), and accessibility (WCAG/Axe) — 187 discovered tests. Opt-in monitoring adds 50 Govmap/Ofek checks (237 total). The chromium, product-setup, and product-authenticated projects remain disabled in playwright.config.ts. GitHub Actions runs product, organuz-api, agent, security, fraud, and accessibility in parallel; local-web is local-only.

Stack Overview

TS Playwright Tests

Active by default: product 60, organuz-api 1, agent 2, security 30, fraud 14, local-web 50, and accessibility 30 — 187 discovered tests. MONITORING_ENABLED=true adds 50 live third-party checks (237 total). chromium (12) and product-setup → product-authenticated (3 + 10) remain disabled with their specs retained.

E2E Product Coverage

tests/product discovers 60 cases across API/public sanity, cellular login, English UI, offline matrix/role contracts, Pixel/Galaxy responsive layouts, and calculator wizard/customer-process journeys. Side-effecting OTP and authenticated-wizard paths are explicitly opt-in.

PY FastAPI

Provides /health, /metrics, /openapi.json, built-in docs at /docs, and automation metadata under /automation.

API Organuz Backend

The organuz-api project tests the Organuz Supabase/PostgREST backend — the /rest/v1/projects resource and edge-function CORS preflights — using the public anon key.

RPC Dev RPC token

The product token-sanity spec opens the dev calculator, captures the UI token off the wire, and calls the dev RPC gateway at organuz.flamiingo.com (POST /?call=<method>) — proving the bundled public token authorizes the gateway and is sent in the request body over HTTPS, never in the URL.

DOC Scalar API Reference

External Scalar docs read the FastAPI OpenAPI schema from localhost:8000/openapi.json.

MON Pushgateway

The Prometheus Pushgateway (prom/pushgateway, host 9091) receives the qa_playwright_* test metrics that scripts/push-qa-metrics.mjs pushes after each run; Prometheus then scrapes it with honor_labels: true.

MON Prometheus

Scrapes FastAPI process metrics from api:8000/metrics and the QA test metrics from the pushgateway, both through server/prometheus.yml.

MON Grafana

Runs on host port 3001 with a provisioned Prometheus datasource and the OrGanuz QA Dashboard.

REP Allure 3

Generated by the CLI and CI workflow, served locally by Nginx, and published by GitHub Pages on main branches.

FAIL Failure Capture

src/fixtures/index.ts attaches screenshots, videos, and traces to Allure after unexpected failures; Playwright is configured with screenshot: only-on-failure, video: retain-on-failure, and trace: on-first-retry.

AGENT QA Orchestrator

Coordinates Azure DevOps, Google Sheets, Playwright, and OneDrive. The CLI-backed runner maps orchestrator cases to real Playwright projects and reports pass/fail evidence back through the agent loop. Its sibling TestPlanAgent goes the other way — given a URL, it drives the Playwright MCP CLI server (npx @playwright/mcp) to explore the live page and generate a TestSuite (npm run agent:plan -- <url> --live).

QA Agent Orchestrator Stack

The QA Agent Orchestrator coordinates multiple testing tools and integrations to automate the verification pipeline:

Azure DevOps

System of record. The orchestrator reads test plans, writes back outcomes, and files bugs idempotently (guards against duplicates).

Provides parameterized input/expected values and environment configurations, and logs live results.

Playwright Runner

OneDrive Store

Durable evidence storage. Returns shareable links that are linked in reported DevOps bugs.

Current Test Mapping

npm run agent:current-tests maps PW-API, PW-PRODUCT, and PW-AGENT to the real organuz-api, product, and agent Playwright projects.

Agent Current-Test Flow

1

Build agent

npm run agent:current-tests first compiles TypeScript with tsc -p tsconfig.json.

2

Create suite

run-current-tests.ts creates stubbed ADO/Sheets/OneDrive connectors and a generated suite for the repository's Playwright projects.

3

Run projects

CliPlaywrightRunner executes --project=organuz-api, --project=chromium, --project=product, and --project=agent as orchestrator cases.

4

Report outcome

The orchestrator uploads report artifacts, writes case results, files bugs for failures, logs Sheets rows, and returns a JSON run summary.

CLI Flow

1

Typecheck

npx tsc --noEmit validates the TypeScript framework before tests run.

2

Start stack

The script starts FastAPI, Scalar, Prometheus, the Pushgateway, and Grafana when local endpoints are not ready.

3

Run tests

npm test executes the active projects — product, organuz-api, agent, security, fraud, local-web, and accessibility — in one run. The local shell flow runs them while the service containers are online, then pushes qa_playwright_* metrics to the Pushgateway.

4

Serve reports

Allure 3 is generated and served through the local Nginx allure service.

Product Matrix Data Contract

The matrix is checked-in test data, split across tests/product/matrix/ — matrix-types.ts, matrix-constants.ts, product-personas.data.ts, and property-scenarios.data.ts, re-exported through the e2e-matrix.data.ts barrel. product-matrix-data-contract.spec.ts asserts the shape of that data (no browser, no network); it encodes the working E2E matrix document so drift is caught in CI.

  • 12 main CALC-ROOF-001 to CALC-ROOF-012 characterization scenarios.
  • 4 personas per main scenario: customer, consultant, company, and company employee.
  • Property types: private house, residential building, commercial, agricultural, and public.
  • Polygon behavior: building, parking, sports court, and mixed building + parking/sports-court flows.
  • Roof and surface types: concrete, tiles, iscoverit, parking, and sports court.
  • Negative coverage below the QUOTABLE_MINIMUM_PANEL_COUNT threshold and UI-only tracking for the no-panel case.
  • Invariants checked: unique scenario ids, arena/panel-mode consistency, empty roof-payload placeholders, and a pinned scenario × persona count.

Per-Role Session Architecture

The dev app rate-limits OTP per phone, so each role logs in once per run (in product-setup) and every per-role spec reuses that session. Missing credentials or a saved session skip cleanly, so the suite is green without secrets.

  • auth.setup.ts logs each role in (phone + fixed dev OTP) and saves storageState to playwright/.auth/product-<role>.json (gitignored); auth.ts maps a role to that file.
  • Per-role specs set test.use({ authRole }); the product fixture loads the saved storageState, and product.resumeSession() restores the session without a new login.
  • ProductAppPage.ts drives login, the password gate, the characterization wizard, and personal-area navigation; ProductFlows / RegistrationFlows compose them into journeys; TokenInterceptor captures the UI token.
  • Three roles sign in: customer, consultant, company. company-employee is modeled in the matrix but has no phone and cannot sign in.

Typed Environmental Errors

Outages are modeled as typed, instanceof-safe errors in tests/product/support/errors.ts so the page object and flows stay free of test-lifecycle decisions.

  • OtpUnavailableError / AppUnavailableError extend a base that restores the prototype and name (Playwright's transpiler otherwise severs extends Error).
  • ProductAppPage, env-gate, and ProductFlows throw these; the test edge decides whether to skip or fail.
  • In practice the one sanctioned skip is token-sanity: when the dev gateway is down and no token can be extracted, beforeEach skips rather than failing the product job.
  • A token that is observed but malformed/drifted still fails as a real regression.

Tags & Gating

  • @other-smoke — the default filter for organuz-api (1) and agent (2), plus chromium when re-enabled. product (60), security (30), fraud (14), local-web (50), and accessibility (30) run everything matched.
  • @ui — marketing-site specs; @organuz-api @contract — the backend contract test.
  • @product @api @sanity — the dev token-sanity spec (@critical/@security on individual checks); @product @roles @e2e — the live per-role specs. The product project has no grep filter, so every matched spec runs.
  • Sanctioned skips cover genuine product outages, CI-blocked geocoding, explicit OTP/wizard gates, local-only marketing specs, unreachable fraud auth backends, and disabled role sessions. The active configuration discovers 187 tests; monitoring raises that to 237.
  • Specs run fully parallel (fullyParallel: true); data-contract and stubbed-agent tests share no state, and role specs reuse read-only saved sessions.

QA Dashboard Metrics

scripts/push-qa-metrics.mjs reads the latest Playwright JSON report (test-results/results.json, override QA_PLAYWRIGHT_RESULTS_PATH) and pushes the metrics to the Prometheus Pushgateway (PUSHGATEWAY_URL, default http://localhost:9091); Prometheus scrapes the Pushgateway with honor_labels: true and Grafana provisions the QA dashboard automatically. FastAPI's /metrics now serves only its own process_* / up metrics — it no longer reads the results file, which retired the old stale-bind-mount refresh hack.

  • qa_playwright_tests_total{project,status} for pass/fail/skipped counts.
  • qa_playwright_duration_seconds{project} for project runtime.
  • qa_playwright_last_run_timestamp_seconds for report freshness.
  • qa_playwright_report_present for “latest report loaded” status.

Backend API and Failure Capture

Organuz Supabase API

  • The organuz-api project (tests/organuz-api/contracts/) targets the Organuz Supabase/PostgREST backend.
  • Base URL and public anon key come from config.json → organuzApi (env override ORGANUZ_API_ANON_KEY).
  • The live contract test asserts the /rest/v1/projects schema: every required field present and non-null, numeric/array field types, and each bilingual (he/en) pair present and non-empty.
  • The OrganuzApi client (read-only) plus RestApiConstants centralize the REST paths, PostgREST filters, and Prefer headers; the anon role is intentionally not permitted to write.
  • The dev product-app RPC gateway (organuz.flamiingo.com) is exercised indirectly by the product token-sanity spec, not by a separate project.

Failure Artifacts

  • src/fixtures/index.ts attaches screenshots, videos, and traces to Allure after unexpected failures.
  • Playwright is configured for screenshot: only-on-failure, video: retain-on-failure, and trace: on-first-retry.
  • The agent orchestrator spec deliberately simulates a runner crash (marked blocked) to prove crash isolation — it passes; it is not an expected-failure demo.
  • Backend/API logging is inverted through an onExchange callback the fixture points at Allure, so the API client has no test-framework dependency.

GitHub Actions

  • typecheck validates TypeScript.
  • tests runs organuz-api, agent, security, fraud, product, and accessibility as a fail-fast: false matrix. chromium and product-authenticated remain commented out; local-web is intentionally local-only.
  • Beyond push / PR / manual dispatch, the workflow also runs on a daily 05:00 Asia/Jerusalem schedule via a DST-aware gate job (two UTC crons, 02:00 + 03:00; the gate lets through only the slot that is the 05:xx hour in Israel). The non-blocking monitoring job still runs on every push/PR.
  • The product shard sets QA_TARGET_ENV: dev (per-target env files env/.dev.env / env/.prod.env, with a root .env fallback) and needs the PRODUCT_PLATFORM_PASSWORD secret (token/public-app sanity open the dev calculator); a missing secret shows as skips, not a red job.
  • The organuz-api, agent, and security shards need no browser; Chromium is installed for the product shard (and the chromium shard when re-enabled).
  • services-smoke starts FastAPI, Scalar, Prometheus, and Grafana.
  • publish-allure merges Allure artifacts and generates Allure 3.
  • deploy-allure publishes the report to GitHub Pages on main or master.
  • report-summary writes Allure, FastAPI, Scalar, and Grafana links into the Actions summary.
